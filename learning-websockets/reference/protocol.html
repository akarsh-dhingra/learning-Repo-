WebSocket protocol cheat sheet

Handshake (§1.3, §4)

GET /path HTTP/1.1
Host: example.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: <16 random bytes, base64>
Sec-WebSocket-Version: 13
Origin: https://app.example.com      ← check it
Sec-WebSocket-Protocol: v1.json      ← optional

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: <see below>
accept = base64(sha1(key + "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"))
"dGhlIHNhbXBsZSBub25jZQ==" → "s3pPLMBiTxaQ9kYGzzhZRbK+xOo="

Not authentication. Do auth and Origin checks before sending 101. Schemes: ws:// (80), wss:// (443, TLS). Always use wss in production.

Frame header (§5.2)

byte 0:  FIN(1) RSV1-3(3) opcode(4)
byte 1:  MASK(1) len(7)
         len 0–125 → actual length
         len 126   → + 2-byte length (≤ 65,535)
         len 127   → + 8-byte length
+ 4-byte masking key   if MASK=1
+ payload
header size: 2 … 14 bytes

Example: server sends “Hello” → 81 05 48 65 6c 6c 6f

Masking (§5.3, §10.3)

client → server: MASK=1 always, fresh random key
server → client: MASK=0 always
unmask: payload[i] ^= key[i % 4]

Purpose: stops script from writing chosen bytes that a broken proxy could cache (cache poisoning). Not encryption.

Opcodes

HexTypeNote
0x0continuationnext fragment of a message
0x1textmust be valid UTF-8
0x2binaryMessagePack, protobuf…
0x8close2-byte code + reason
0x9pingreply with pong, same data
0xApongalso usable as one-way heartbeat

Control frames (≥ 0x8): payload ≤ 125 bytes, never fragmented, may arrive between the fragments of a data message.
