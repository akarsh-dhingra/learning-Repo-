Lesson 0009 · Build · ~75 min

A Gather-style world: ticks & interest management

Rooms where everyone sees everyone don't survive 300 people. Make the server authoritative, send updates on a fixed tick, and tell each player only about what's near them.

You'll build: a 2D world server (separate from the whiteboard) with server-authoritative movement, a 10 Hz tick, a spatial grid, per-player enter/moves/leave deltas and proximity chat, plus a canvas client and a bot swarm to measure it. Done when: 7/7 checks pass and you've reproduced the numbers below.

1. Three game-server ideas you need

  1. Server-authoritative. Clients send intent (“I want to be at x,y”). The server clamps it (max 50 px per move, inside the world) and its answer is the truth. Never trust client positions in anything with stakes.
  2. Fixed tick. Apply input as it arrives, but send state once per tick (100 ms here). Outbound messages per player per second are capped at the tick rate, however many moves happen.
  3. Interest management. A player only receives players within RADIUS. Find them fast with a spatial grid: cell size = radius, so neighbours are always in the 3×3 cells around you. No O(N²) distance checks.

2. Measured on your machine

Read the two columns separately. Messages stay at players × 10 in both modes: that's the tick doing its job. Bytes drop about 10×: that's interest management. And at 1,000 players with interest off, one tick takes 74 of its 100 ms. A bit more load and the world starts lagging for everyone in it.

3. Build it

Step 1: the grid

const cellKey = (x: number, y: number) => `${Math.floor(x / RADIUS)},${Math.floor(y / RADIUS)}`;
function nearby(p: Player): Player[] {
  const cx = Math.floor(p.x / RADIUS), cy = Math.floor(p.y / RADIUS), out: Player[] = [];
  for (let dx = -1; dx <= 1; dx++) for (let dy = -1; dy <= 1; dy++)
    for (const o of grid.get(`${cx + dx},${cy + dy}`) ?? [])
      if (o !== p && (o.x - p.x) ** 2 + (o.y - p.y) ** 2 <= RADIUS ** 2) out.push(o);
  return out;
}
// on every move: gridRemove(p); update p.x/p.y; gridAdd(p); p.dirty = true

Step 2: move = clamp, don't trust

.on("move", z.object({ x: z.number(), y: z.number() }), ({ ws, data }) => {
  const p = ws.data.player;
  let dx = data.x - p.x, dy = data.y - p.y;
  const d = Math.hypot(dx, dy);
  if (d > MAX_STEP) { dx *= MAX_STEP / d; dy *= MAX_STEP / d; }
  gridRemove(p); p.x = Math.round(clamp(p.x + dx, 0, W)); p.y = Math.round(clamp(p.y + dy, 0, H)); gridAdd(p);
  p.dirty = true;                            // sent on the next tick, not now
})

Step 3: the tick, with per-player deltas

setInterval(() => {
  for (const p of players.values()) {
    const enter = [], moves = [], ids = new Set<string>();
    for (const o of nearby(p)) {
      ids.add(o.id);
      if (!p.seen.has(o.id)) enter.push({ id: o.id, name: o.name, x: o.x, y: o.y }); // new in view: full info
      else if (o.dirty) moves.push([o.id, o.x, o.y]);                               // known: compact tuple
    }
    const leave = [...p.seen].filter((id) => !ids.has(id));
    p.seen = ids;
    const you = p.dirty ? { x: p.x, y: p.y } : undefined;   // the server's verdict on YOUR position
    if (enter.length || moves.length || leave.length || you)
      p.ws.send(JSON.stringify({ type: "tick", data: { you, enter, moves, leave } }));
  }
  for (const p of players.values()) p.dirty = false;
}, TICK_MS);

Notice the trade-off: every player's view is different, so you serialise per player, and you lose “serialise once”. That's why the grid and the radius matter so much: they keep each message small.

Step 4: proximity chat

chat.send goes to [p, ...nearby(p)] and acks { heardBy }. That's Gather's “only people near you can hear you”, implemented with the same function.

6. System-design rep

60 seconds: “A Gather space hosts a 2,000-person company all-hands. Everyone is in one big room. What do you do?”

A strong answer covers…
  • Interest management alone fails when everyone crowds into one spot: the radius contains 2,000 people. Cap visible players (nearest K), and show the rest as an aggregate count.
  • Lower the tick rate for far or idle avatars, and send moves only above a distance threshold.
  • Broadcast the speaker's stream separately (one-to-many, CDN-like) rather than through the position server.
  • One space = one owner process (lesson 0010). Cap players per space and build an overflow/“spectator” mode.
