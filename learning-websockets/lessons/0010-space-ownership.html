Lesson 0010 · Build · ~75 min

Space ownership, presence & failover

Pattern B from lesson 0003. Each Gather space lives on exactly one node. A directory tells clients where. When a node dies, its spaces move, and nothing else does.

You'll build: a cluster of world nodes that register themselves with heartbeats, a directory service using rendezvous hashing, owner checks (HTTP 421), rebalancing when a node returns, cluster-wide presence, and a client that follows its space wherever it moves. Done when: 6/6 checks pass, including a real crash-and-failover.

1. Why owners, not a backplane, for worlds

The 0009 tick needs every player's position in one process's memory: the grid, nearby(), the clamp. Spreading one space across nodes would mean shipping every move through Redis just to rebuild that view everywhere. So route by space: all of a space's players connect to its owner, and the owner runs the simulation. Figma does the same for documents and Discord for guilds (lesson 0003).

2. The four building blocks

Membership: TTL heartbeats

const beat = () => redis.send("SET", [`node:${id}`, url, "EX", "5"]);
beat(); setInterval(beat, 1500);   // crash = stop refreshing = key expires within 5s = gone

No one has to detect the crash. Absence is the signal. Pick the TTL as a trade-off: shorter means faster failover but more false alarms on a GC pause.

Ownership: rendezvous hashing

export function ownerOf(space: string, nodes: Node[]) {
  let best, bestScore = -1n;
  for (const n of nodes) {
    const score = BigInt(Bun.hash(`${space}|${n.id}`));  // deterministic in every process
    if (score > bestScore) { best = n; bestScore = score; }
  }
  return best;
}

Every process computes the same owner with no coordination. When a node leaves, only its spaces get a new highest score, and everyone else's winner is unchanged. Consistent hashing with a ring gives the same property. Rendezvous is just shorter to write[1].

Enforcement: 421 and 4010

  • On upgrade, a node computes ownerOf(space). If it isn't the owner, it returns HTTP 421 Misdirected Request, and the client asks the directory again. Stale routing is detected, not trusted.
  • Every second, a node refreshes membership. If a space it hosts now belongs to someone else (a node came back), it closes those sockets with 4010 space moved, and the clients follow.
  • Cap players per space (HTTP 503 when full). A hot space must not take its node down.

Presence: sorted set with heartbeat scores

ZADD presence:{space} <now> '{"id":"…","name":"…"}'           // on join, and every 5s for local players
ZREM presence:{space} '{"id":"…","name":"…"}'                 // on leave
ZRANGEBYSCORE presence:{space} <now − 15s> +inf              // "who's online": stale = crashed node, ignored

This fixes 0008's leak: a crashed node never runs its cleanup, but its entries stop being refreshed and fall out of the window.

3. Build it

New folder: build/world-cluster, starting from your 0009 world. Reference: labs/0010-space-ownership/ (cluster.ts, directory.ts, space-node.ts). Changes to make:

  1. Turn the single world into Map<spaceId, { players, grid }>, chosen by ?space=. The tick loops over spaces.
  2. cluster.ts: liveNodes(), ownerOf(), startHeartbeat(), onlineIn().
  3. directory.ts: /assign, /nodes, /presence, and it serves the page. It holds no sockets at all.
  4. Node: owner check (421), capacity (503), rebalance (4010), presence writes, and POST /__crash for the failover test (dev only).
  5. Client: fetch("/assign") → connect → on any close, backoff and ask the directory again.

6. System-design rep

5 minutes on paper: “Design the realtime layer of a Gather-like product: 50k concurrent users, 5k spaces, the biggest has 500 people.” Then compare.

A strong answer covers…
  • Pattern B. Space owners chosen by rendezvous/consistent hashing over live nodes, a directory for lookup, and clients connecting directly (or via an LB that routes by space).
  • Inside a space: authoritative 10 Hz tick, grid-based interest management, proximity chat (0009).
  • Sizing: say 2k sockets and ~20 spaces per node at the measured costs, so ~25–40 nodes with headroom. The 500-person space is the hot spot: cap it, and give it its own node if needed.
  • Failure: heartbeat TTL → reassignment in ~5 s; clients re-ask the directory with jittered backoff. Positions are rebuilt from reconnecting clients, and durable space data lives in a DB.
  • Presence via TTL'd heartbeats. A/V goes over WebRTC/SFU, with the socket layer only doing signaling.
