Cache-aside (lazy loading)

  1. GET key from Redis
  2. Hit → return it
  3. Miss → query the database
  4. SET key value EX ttl → return it

The app fills the cache, not Redis. Data can be stale for up to the TTL; on writes, DEL the key to invalidate it. Source

Commands so far

CommandResultNote
SET k vOKOverwrites the value and clears any TTL
SET k v EX 60OKValue and TTL in one atomic command, which is what you want
SET k v NXOK / (nil)Only sets it if the key doesn't exist
GET kvalue / (nil)
EXPIRE k 601 / 0Adds or refreshes a TTL on an existing key
TTL ksecs / -1 / -2-1 no expiry · -2 no such key
INCR knew intAtomic; keeps the existing TTL
DEL kcountRemoves the key (cache invalidation)

TTL survives commands that change a value in place (INCR, LPUSH, HSET). It's cleared by commands that replace the key (SET, DEL, GETSET). Source

docker exec -it redis-stack redis-cli
open http://localhost:8001   # RedisInsight

node-redis

import { createClient } from "redis";
const redis = createClient({ url: "redis://localhost:6379" });
redis.on("error", (e) => console.error(e));
await redis.connect();

await redis.set("post:10", JSON.stringify(obj), { EX: 600 });
const hit = await redis.get("post:10");          // string | null
await redis.set("lock:seat:4", "1", { NX: true }); // set-if-absent
