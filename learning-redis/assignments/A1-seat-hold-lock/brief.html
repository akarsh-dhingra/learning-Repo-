Build a seat-hold lock that can't double-book

BookMyShow, the video's example. Fifty people tap the same seat in the same instant. Exactly one of them should get it, even when a server freezes partway through a payment.

When you're done: npm test shows 15/15, and you can defend every line in an interview: why the token is random, why release is a script, why the fence exists, and when you wouldn't use Redis for this at all.

3. Hints (open only when stuck)

Part 1: how do I run a script from node-redis? 
await redis.eval(SCRIPT, { keys: [k1, k2], arguments: [a1, String(a2)] });
Arguments must be strings. Inside Lua, redis.call("set", KEYS[1], ARGV[1], "NX", "PX", ARGV[2]) returns a falsy value when NX blocks the write.
Part 1: why can't I INCR the fence before or after the SET as a separate call? Before: failed acquires bump the counter (a test checks for this). After: a client can stall between its SET and its INCR. Its lease can expire and someone else can acquire and INCR, and then the stalled client gets the higher fence even though it's the stale one. Do both in one script.
Part 2: what's the release script? Get the key and compare it with your token. Delete only if they're equal, otherwise return 0. Redis 8.4+ has a single command for this (DELEX key IFEQ token), but your container runs 7.4, so use Lua. Redis docs
Part 3: < or ≤? Reject fence < last. The same holder writing twice with the same fence is legitimate.
Part 5: the 50-user test says 0 winners Your retry budget runs out before the first holder releases. Everyone else should get "taken" (they got the lock after the winner) or "busy" (they gave up), but somebody must win. Check that you actually release in finally and that you sleep between attempts.

5. Stretch goals (optional)

  1. Auto-extend (watchdog): in withLock, extend the lease every ttl/3 while fn runs, and stop when it finishes. Add a test where fn takes 3× the TTL and still holds the lock.
  2. Seat hold with payment: model the real flow. holdSeat takes the lock with a 10-minute TTL, confirmPayment(lock) writes the booking with the fence and releases, and abandon just lets the TTL expire. Which of these needs the fence?
